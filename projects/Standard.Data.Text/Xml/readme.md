# XML 序列化器

## 定位

XML 序列化器实现 `ISerializer`，将对象转为 XML 文本。它是 Sonic.Data 的 **结构化标记文本格式**。

## 为什么还需要 XML？

JSON 几乎统治了现代 API。但 XML 在两个领域仍然不可替代：

1. **企业/政府系统集成**：SOAP、XSD、WSDL 生态系统仍在大规模运行。银行间清算、税务申报、医疗记录交换——这些场景的消息格式是
   XML，不需要讨论。

2. **自描述性超越 JSON**：XML 的命名空间（`xmlns`）和属性（`<Person age="30">`）提供了 JSON 键值对无法表达的元信息层级。JSON
   Schema 试图填补这个差距，但 XML+XSD 在这一领域的成熟度领先了二十年。

## XML 序列化器的设计取舍

- **`<null />` 自闭合标签**：JSON 的 `null` 简洁但含义模糊——缺失字段和 null 字段在 JSON 中无法区分。XML 可以表达
  `<name xsi:nil="true" />` 或省略标签，提供更丰富的语义。
- **数组元素包裹在 `<item>` 中**：XML 没有原生数组概念。`<items><item>A</item><item>B</item></items>`
  是约定俗成的表示法。理想的实现应该支持通过属性自定义包裹标签名，当前版本暂未提供。
- **字符串自动转义 XML 特殊字符**：`<`、`>`、`&` 是 XML 的保留字符，数据中出现时必须转义。序列化器在写入时自动处理。

## 不应该承担什么职责？

- **不应验证 XML Schema**：XSD 验证属于 DataContract 维度，不嵌入序列化流程。
- **不应支持命名空间**：命名空间增加了显著的实现复杂度但覆盖面窄。如果你的消息需要 XML 命名空间，当前实现不适用。

## 典型场景

- **SOAP Web Service**：请求/响应 body 是 XML，字段映射到 `ISerializer` 的容器操作。
- **遗留系统对接**：主数据管理系统输出 XML，新系统消费（投影层屏蔽 XML/JSON 差异）。
- **配置文件**：`app.config`、`web.config` 格式。
