# Nyar 方言系统

## 什么是方言？

**方言不是语言，而是支持语言运行的最小化指令集合。**

用例子来说明：

- **Java** 不是方言， **JVM 字节码**才是方言
- **Lua** 不是方言， **Lua 字节码**才是方言
- **Python** 不是方言， **Python 字节码**才是方言
- **C** 不是方言， **x86-64 汇编**才是方言

方言是语言运行时的"底层表示"，是意图优化和代码生成的基础。

## 方言之间：没有高低，只有相对

Nyar 的方言系统 **没有绝对的"高级"和"低级"之分**。一切都是相对的。

例如：

- JavaScript 既可以作为 **输入**（前端将 JS 转换为意图）
- JavaScript 也可以作为 **输出**（后端将意图转换为 JS）

关键区别不是"层级"，而是：

| 维度      | 说明                                             |
|-----------|--------------------------------------------------|
| **What**  | 做什么——意图本身（排序、卷积、查询）             |
| **How**   | 怎么做——实现策略（快速排序、归并排序、基数排序） |
| **Where** | 在哪里做——目标平台（x86-64、WASM、JVM、FPGA）    |

## 方言网络：任意连接，按需转换

方言不是单向的降级链，而是一个 **相互连接的网络**：

```
┌─────────────────────────────────────────────────────────────┐
│                          方言网络                             │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Tensor ────┐      ┌──── Regex      ┌─── x86-64             │
│             │      │                 │                       │
│  Data ──────┼─── Core ────┼───── JVM                     │
│             │      │                 │                       │
│  Web ───────┘      └──── Standard ───┴─── WASM            │
│                                                              │
│  └── 任意方言都可以直接或间接转换为其他方言 ──┘              │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**特点**：

- 没有强制的中间步骤
- Tensor 方言可以直接转换为 x86-64，不需要经过 Standard
- Core 方言可以转换为 Web，也可以转换为 JavaScript
- 一切取决于优化需要和成本模型

## 方言设计原则

### 1. 不可归约性（对于 Core 方言）

Core 方言中的每个操作都应该是 **不可再分的语义原子**——无法用该方言的其他操作组合表达。

Core 方言仅有 15 个语义原子：

- **值**：Literal
- **纯运算**：Add, Sub, Mul, Div, Rem, Neg, Not, Cmp
- **数据聚合**：Tuple, Project
- **内存**：Alloc, Free, Load, Store
- **控制流**：Label, Branch, Phi, Call, Ret
- **效应**：Perform, Handle

### 2. 优化友好性

方言设计必须考虑 **优化器的推理能力**。

例如：

- Core 方言保留 `Add` 而非全部用 `Call`，因为优化器需要知道 `Add` 满足交换律、结合律
- 如果只有 `Call`，优化器完全无法进行代数化简

### 3. 领域专用性

方言应该为特定领域提供 **抽象的意图节点**，让优化器能理解领域语义。

例如：

- **Tensor 方言**：提供 `Conv2d`, `MatMul`, `BatchNorm` 等节点，让优化器能进行算子融合
- **Web 方言**：提供 `DOMQuery`, `DOMUpdate`, `Fetch` 等节点
- **Data 方言**：提供 `Scan`, `Filter`, `Join`, `Agg` 等关系代数节点

## 方言集合

Nyar 提供以下内置方言：

| 方言         | ID | 用途                                         |
|--------------|----|----------------------------------------------|
| **Core**     | 0  | 基础语义原子，所有方言的"通用语"             |
| **Standard** | 1  | 通用高级类型和操作（字符串、数组、结构体等） |
| **Data**     | 2  | 数据库查询与数据处理（关系代数）             |
| **Tensor**   | 3  | 深度学习与张量运算                           |
| **Web**      | 4  | Web 前端与后端                               |
| **Regex**    | 5  | 正则表达式                                   |
| **Proof**    | 6  | 形式化验证                                   |
| **Hardware** | 7  | 硬件描述与综合                               |
| **Shader**   | 8  | GPU 着色器编程                               |
| **Game**     | 9  | 游戏 AI 与行为树                             |
| **Schedule** | 10 | 任务调度与资源分配                           |
| **Agent**    | 11 | 多智能体规划与协调                           |
| **Quantum**  | 12 | 量子电路与量子算法                           |

## 方言转换：升降自如

方言之间的转换不是单向的降级，而是 **双向的升降**：

```
升（抽象化）：Core → Standard → Tensor
降（具体化）：Tensor → Standard → Core
```

但这不是强制路径，任何方言都可以 **直接转换**为其他方言：

- Tensor → x86-64（直接代码生成，绕过 Standard）
- Web → JavaScript（直接转换，绕过 Core）
- Regex → Core → Regex（在不同表示之间切换）

**转换规则**：

- 每个方言定义与其他方言的转换规则
- 优化器根据成本模型自动选择最佳路径
- 同一意图可以同时存在于多个方言中（EGraph 共存）

## 为何这样设计？

### 1. 优化器可以在任意层面工作

- 在 Tensor 方言层面：进行算子融合、内存重用
- 在 Standard 方言层面：进行通用优化（内联、常量折叠）
- 在 Core 方言层面：进行指令选择、寄存器分配

### 2. 前端可以"按需选择"

- 深度学习编译器：直接生成 Tensor 方言
- 通用语言编译器：生成 Standard 方言
- 底层系统语言：直接生成 Core 方言
- Web 开发者：直接生成 Web 方言

### 3. 保持最大灵活性

- 新增领域：只需添加新的方言，无需修改 Core
- 新增目标：只需添加新的转换规则，无需改变现有方言
- 任意语言都可以作为输入或输出

## 关键区别

| 概念         | 示例                               | 说明                 |
|--------------|------------------------------------|----------------------|
| **语言**     | Java, Python, Lua                  | 用户编写代码的语言   |
| **方言**     | JVM 字节码, Python 字节码, Nyar IR | 编译器内部的意图表示 |
| **目标平台** | x86-64, WASM, ARM                  | 最终执行的硬件/平台  |

**Nyar 的方言不是源语言，而是连接源语言和目标平台的桥梁。**
