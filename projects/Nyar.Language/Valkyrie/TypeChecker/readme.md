# Valkyrie.TypeChecker 类型系统与检查规范

## 上半部分：类型系统

### 1. 类型构造

Valkyrie 的类型系统以 **结构类型（structural typing）** 为基础，所有类型的身份由其 **公开方法行**
决定。类型构造分为原始类型、复合类型、函数类型与类型组合，本节给出完整的类型语法及语义。

#### 1.1 原始类型

原始类型是内建的不可再分类型，包括：

- 有符号整数：`i8`, `i16`, `i32`, `i64`
- 无符号整数：`u8`, `u16`, `u32`, `u64`
- 浮点数：`f32`, `f64`
- 布尔类型：`bool`
- 无值类型：`void`（表示永不返回或不可达，即 ADT 中的 `0`）
- 任意类型：`any`（所有非 `null` 类型的顶类型）
- 可空任意类型：`any?`（真正的顶类型，包含 `null`）
- 空类型：`null`（独立类型，只与 `any?` 和可空类型兼容）

**重要**：`any` 不包括 `null`，`any?` 才是绝对顶层。`void` 是底层类型，对任意类型 `τ` 有 `void <: τ`。

每个原始类型都拥有由标准库定义的公开方法行，例如 `i32` 提供 `to_string: () -> utf8`，`bool` 提供 `not: () -> bool`
等。这些方法在类型检查时参与方法行兼容性计算。

#### 1.2 元组类型

- `unit` 是空元组 `()`，仅有唯一值 `()`。
- 元组类型写作 `(τ₁, τ₂, ..., τₙ)`，其中 `τᵢ` 为任意类型。
- 元组类型结构等价：`(τ₁, τ₂) ≡ (σ₁, σ₂)` 当且仅当对应位置类型等价。
- 元组类型的方法行：元组本身不带方法，除非通过扩展赋予。默认无公开方法。

#### 1.3 数组类型

- 动态长度数组：`[τ]`，元素类型为 `τ`。
- 固定长度数组：`[τ; N]`，其中 `N` 为编译期常量整数。
- 数组支持索引访问（视为内置方法 `get` 和 `set`），其方法行包含 `get: (i32) -> τ` 和 `set: (i32, τ) -> unit` 等。

#### 1.4 函数类型

函数类型写作 `(τ₁, τ₂, ..., τₙ) -> τ / ε`，其中：

- `τᵢ` 为参数类型，`τ` 为返回类型。
- `ε` 为 effect 集合，若省略则默认空集 `{}`。
- 参数类型是 **逆变** 的，返回类型是 **协变** 的，effect 集合是 **协变** 的（子类型允许更小的 effect 集）。

#### 1.5 类类型（`class`）

类使用 `class` 定义：

```valkyrie
class Point {
    [get] x: i32
    [set] y: i32
    public f() -> i32 { ... }
    private g() -> bool { ... }
}
```

- `class` 定义的类型是 **引用类型**，其实例总是在堆上分配，变量持有引用。
- 类的公开方法行由 `public` 方法和属性脱糖而来：
  - `[get]x` 贡献 `get_x: () -> i32`
  - `[set]y` 贡献 `set_y: i32 -> unit`
  - `public f` 按签名 `(params) -> ret / eff` 加入公开行
  - `private g` 不出现在公开行中。
- 类类型在类型系统中完全由其 **公开方法行** 表征，类名本身并不赋予额外的名义身份。因此，任何具有相同方法行的类型均可与该类类型兼容。
- 类默认是引用的，因此变量类型实际上是 `&Point`（引用），但为了语法简洁，`&` 可省略。对于值类型（如 `struct`），需要显式 `&T`
  表示引用。

#### 1.6 封闭类层次（`unite`）

`unite` 用于定义 **封闭的代数数据类型（ADT）**：

```valkyrie
unite Option<T> {
    Some { value: T }
    None
}
```

它同时定义：

- 一个 **抽象父类** `Option<T>`，不能直接实例化。
- 若干个 **具体子类** `Some<T>` 和 `None`，均继承自 `Option<T>`。
- 该层次是 **封闭的**，外部不能再添加子类。

`unite` 的类型地位：

- 每个子类 `Some<T>`、`None` 都是独立的类型，且 `Some<T> <: Option<T>`，`None <: Option<T>`。
- 抽象父类 `Option<T>` 的方法行为 **所有子类公开方法行的交集**。
- `unite` 的父类与开放联合 `Some<T> | None` 不同：后者是一个匿名的联合类型，方法行为交集；前者是一个带有抽象标记的封闭类型，不能混为一谈。

**`unite` 与 `union` 的根本区别**：

- `unite` 创建 **具有名义的封闭类层次**，具有抽象的父类型。
- `A | B` 是纯粹的 **类型组合**，不创建新类型，只是匿名联合。

#### 1.7 联合类型（`|`）

`τ₁ | τ₂` 表示运行时可能为 `τ₁` 或 `τ₂` 的值。没有抽象父类，没有封闭性。

- 方法行：`methods(τ₁ | τ₂) = methods(τ₁) ∩ methods(τ₂)`，即仅能调用两方共同支持的方法。
- 子类型规则遵循分布律，详见后文。

联合类型常与 `unite` 配合使用，例如 `Nullable<T> = T | null` 即是一个开放联合，不创建新类型。

#### 1.8 交集类型（`&`）

`τ₁ & τ₂` 表示同时属于 `τ₁` 和 `τ₂` 的值。

- 方法行：`methods(τ₁ & τ₂) = methods(τ₁) ∪ methods(τ₂)`。若存在方法名冲突且签名不兼容，交集类型非法。
- 主要用作窄化后的变量类型：`if x is Type` 的真分支中 `x` 的类型被更新为 `原类型 & Type`。

#### 1.9 差集类型（`-`）

`τ₁ - τ₂` 表示属于 `τ₁` 但不属于 `τ₂` 的值。

- 主要用于窄化的假分支：`if x is Type` 的假分支中 `x` 的类型为 `原类型 - Type`。
- 方法行继承自 `τ₁`。
- 差集不是用户直接编写的类型，而是编译器内部推导用的类型。

#### 1.10 可空类型（`T?`）

根据 `null` 的设计，可空类型可看作 `T | null`，也可写成 `Nullable<T>`（用户定义）。`null` 类型本身只与 `any?` 和
`Nullable<T>` 兼容，不与 `any` 兼容。

#### 1.11 引用类型 `&T`

- `class` 定义的实例默认为引用，省略 `&`；值类型（如 `struct`）需要使用 `&T` 来获取引用。
- `&` 是 **不变（invariant）** 的：`&T <: &S` 当且仅当 `T ≡ S`。由于类是引用且结构子类型通过方法行判断，实际上 `class A`
  的值可以赋给 `class B` 的变量当方法行覆盖时——这并不违反引用不变性，因为 `A` 和 `B` 是不同的引用类型，但它们的值（引用）仍然指向各自的对象，方法分派通过
  witness table 或 vtable 完成，不会破坏类型安全。

### 2. 方法行与行多态

**方法行（method row）** 是类型的核心组成部分，它是一个从方法名到方法签名的映射，并带有一个可选的 **行变量**
表示未知的剩余部分。形式化表示：

```
ρ ::= ∅ | { m : σ } ∪ ρ | ρ̂
```

其中 `σ` 是方法签名，包括参数类型、返回类型和 effect 集。

每个类型 `τ` 都关联一个方法行 `methods(τ)`：

- 原始类型：由标准库固定。
- 类类型：由 `public` 方法和属性脱糖后提取。
- `unite` 父类：各子类方法行的交集。
- `unite` 子类：自身的公开方法行。
- 联合 `τ₁ | τ₂`：交集。
- 交集 `τ₁ & τ₂`：并集（无冲突时）。
- 函数类型、元组、数组等：一般没有方法（或仅有内置方法）。
- 行变量 `ρ̂` 在泛型约束或结构类型推断中由编译器生成，用于表示“除已知方法外的其余部分”。

**结构类型与行多态**：Valkyrie 的结构类型自动表现为行多态。泛型约束 `T : { foo: () -> i32 }` 表示 `T` 的公开方法行至少包含
`foo` 方法，编译器内部用行变量捕获剩余部分。不需要任何类似 `..` 的语法，因为结构类型本身即开放。

### 3. 子类型关系

Valkyrie 采用 **代数子类型** 框架，子类型关系 `<:` 定义如下：

#### 3.1 基本公理

- `τ <: τ` （自反）
- `τ <: any?` （任何类型都是可空任意类型的子类型）
- `void <: τ` （底层）
- `null <: any?` 且 `null <: Nullable<T>`，但 `null` 不 `<: any` 也不 `<: 具体类型 T`（除非 `T` 显式允许）

#### 3.2 元组与数组

- `(τ₁, τ₂) <: (σ₁, σ₂)` 当 `τᵢ <: σᵢ` （协变）
- `[τ] <: [σ]` 当 `τ <: σ` （协变，但写操作可能破坏安全，由运行时检查或编译器警告处理）
- `[τ; N] <: [σ; N]` 当 `τ <: σ`，长度必须相同

#### 3.3 函数类型

- `(σ₁,…,σₙ) -> τ / ε <: (σ′₁,…,σ′ₙ) -> τ′ / ε′` 当且仅当：
  - 参数个数相同，
  - `σ′ᵢ <: σᵢ` （参数逆变），
  - `τ <: τ′` （返回协变），
  - `ε ⊆ ε′` （effect 协变）。

#### 3.4 类与结构类型

类类型 `C` 等价于其公开方法行 `ρ_C`。因此 `C <: D` 当且仅当 `ρ_C` **覆盖** `ρ_D`，即：

- `ρ_C` 包含 `ρ_D` 中所有方法名。
- 对于每个方法 `m`，若 `ρ_D(m) = (P₁…→R / ε)`，则 `ρ_C(m) = (P′₁…→R′ / ε′)` 且满足：
  - `P₁ <: P′₁` （参数逆变：实际方法接受更宽泛的输入），
  - `R′ <: R` （返回协变），
  - `ε′ ⊆ ε` （effect 更少）。

注意，`ρ_C` 可以拥有比 `ρ_D` 更多的方法（宽度子类型）。

#### 3.5 联合类型

- `τ₁ | τ₂ <: σ` 当 `τ₁ <: σ` 且 `τ₂ <: σ`。
- `τ <: σ₁ | σ₂` 当 `τ <: σ₁` 或 `τ <: σ₂`。
- 交换、结合、幂等律成立。

#### 3.6 交集类型

- `τ <: σ₁ & σ₂` 当 `τ <: σ₁` 且 `τ <: σ₂`。
- `τ₁ & τ₂ <: σ` 当 `τ₁ <: σ` 或 `τ₂ <: σ`。
- `τ & τ ≡ τ`，交换结合成立。

#### 3.7 差集类型

- `τ₁ - σ <: τ₁`。
- 若 `τ₁ <: τ₂`，则 `τ₁ - σ <: τ₂`（差集不丢失父类型信息）。
- 差集的主要用途是窄化，例如 `τ - σ` 在 `σ` 与 `τ` 不相交时等价于 `τ`，否则类型系统保守地保留差集形式直到进一步窄化。

#### 3.8 `unite` 子类型

- `Some<T> <: Option<T>`
- `None <: Option<T>`
- `Option<T>` 与 `Some<T> | None` 不同，`Option<T>` 是一个抽象封闭类型，不能通过 `|` 重新构造。

#### 3.9 泛型与声明点方差

泛型参数可用 `+`（协变）、`-`（逆变）标注，未标注则 **不变**。这影响类型兼容性：

- 协变 `class Box<+T> { get: () -> T }`：若 `A <: B`，则 `Box<A> <: Box<B>`。
- 逆变 `class Sink<-T> { set: T -> unit }`：若 `A <: B`，则 `Sink<B> <: Sink<A>`。
- 不变 `class Ref<T> { get: () -> T; set: T -> unit }`：`Ref<A>` 与 `Ref<B>` 无子类型关系，除非 `A ≡ B`。

#### 3.10 引用类型的不变性

`&T` 为不变，但 `class` 类型隐式引用且子类型基于方法行判断，这本质上是一种特殊的引用子类型化，不影响内存安全，因为 `class`
对象的方法调用是动态分派，字段访问被封装在方法内，外部无法直接覆写引用目标的对象布局。

---

### 4. Effect 系统

Effect 集 `ε` 是函数类型的一部分，表示函数可能产生的副作用。

- 每个方法签名和函数类型都携带 effect 集。
- 函数体内部调用其他函数时，其 effect 集会累积到当前函数。
- 函数声明必须显式写出允许的 effect 集（可省略为空），若函数体产生的 effect 不是声明的子集，则类型错误。
- Effect 集在子类型中协变：`ε ⊆ ε′` 意味着更少 effect 的函数是子类型。

内置 effect 可能包括 `io`, `throw`, `async` 等，具体集合由语言定义。类型检查器只负责检查 effect 传播的一致性，不关心具体语义。

---

### 5. 类型等价

类型等价 `≡` 是类型检查中判断类型是否可互换的依据。Valkyrie 采用结构等价：

- 原始类型各自等价。
- 元组、数组按结构等价。
- 类类型等价于其公开方法行，因此两个类具有相同方法行时视为相同类型（即便类名不同）。
- 联合、交集、差集满足集合论代数律：交换、结合、分配、幂等。
- 函数类型等价当参数、返回、effect 集均等价。

等价关系在泛型实例化、类型窄化、赋值检查时被频繁使用。

## 下半部分：类型检查

### 6. 符号与作用域

类型检查器维护一个作用域栈，每个作用域包含：

- 符号表：变量名 → 类型（可能是窄化后的类型）
- 泛型参数环境
- 当前函数声明的 effect 集上限

作用域操作：

- `define(name, type)`: 在当前作用域声明符号，不允许重复。
- `resolve(name)`: 沿作用域链查找符号，返回其类型（可能受窄化影响）。
- `narrow(name, type, branch)`: 在特定分支内将变量的类型临时更新为更窄类型。

---

### 7. 表达式类型检查

表达式类型检查采用自底向上的方式，每个表达式返回一个三元组 `(type, effect_set, constraints)`，其中约束会被求解器处理。

#### 7.1 字面量

- 整数 `42` → `i32`（默认），无 effect。
- 浮点 `3.14` → `f32`。
- 布尔 `true`/`false` → `bool`。
- 文本 `"hello"` → `literal_text`（进入 `HIR` 前的字面量占位类型）。
- `null` → `null`。
- `void` 表达式 → `void`。

#### 7.2 变量引用

- 查找作用域，返回变量绑定的类型（可能是窄化后的类型）。

#### 7.3 成员访问 `e.m`

1. 检查 `e`，得到类型 `τ` 和 effect `ε₁`。
2. 从 `methods(τ)` 中查找名为 `m` 的方法签名 `(params) -> ret / ε₂`。
  - 若 `m` 是属性访问器，参数为零。
3. 若找到，表达式类型为 `ret`，总 effect 为 `ε₁ ∪ ε₂`。
4. 若找不到，报错。

#### 7.4 方法调用 `e.m(args)`

在成员访问的基础上，还检查参数：

1. 计算参数列表类型 `τ_args`。
2. 对每个位置，要求 `τ_argᵢ <: paramᵢ`（实际参数是形式参数的子类型）。
3. 返回类型和 effect 同成员访问。

#### 7.5 函数调用 `f(args)`

1. 检查 `f`，类型必须是函数类型 `(σ₁,…) -> τ / ε`。
2. 参数匹配：要求每个实参类型是形参的子类型。
3. 表达式类型为 `τ`，effect 为 `ε`。
4. 若 `f` 是泛型函数，则需要推断或显式提供类型实参，并替换约束。

#### 7.6 元组构造 `(e₁, e₂, ...)`

- 每个元素各自检查，得到类型 `τᵢ`。
- 构造类型为 `(τ₁, τ₂, ...)`，effect 为各元素 effect 的并集。

#### 7.7 数组构造 `[e₁, e₂, ...]`

- 若非空，查找所有元素类型的最小上界 `τ`，数组类型为 `[τ]`。
- 若为空 `[]`，需要上下文类型注解来确定 `τ`。
- effect 为所有元素 effect 的并集。

#### 7.8 类实例化 `Point { x: 3, y: 5 }`

- 检查类定义，获取字段（通过 `[get]`、`[set]` 等脱糖）的初始化要求。
- 检查每个提供的字段值是否类型兼容。
- 返回类型为类类型，effect 为初始化表达式的 effect 并集。

#### 7.9 `unite` 构造

- `Some { value: expr }`：检查 `expr` 类型与泛型参数匹配，返回 `Some<T>`，同时它也是 `Option<T>` 的子类型。
- `None`：无参数，返回 `None` 类型。

#### 7.10 `as` 强制转换

- `e as τ`：检查 `e` 类型与 `τ` 的兼容性（可能成功），类型系统相信程序员，表达式类型为 `τ`。可能插入运行时检查，但类型检查不负责。

#### 7.11 `as?` 安全转换

- `e as? τ`：返回类型为 `Option<τ>`（或 `τ | null`），需结合模式匹配使用。

#### 7.12 `is` 类型测试

- `e is τ`：表达式类型为 `bool`，不直接改变类型，但可触发窄化（见控制流窄化）。

### 8. 控制流与窄化

类型窄化是根据运行时测试（`is`、`match`、`as?` 等）在特定控制流分支中临时更新变量类型。

#### 8.1 `if` 语句中的窄化

对于 `if (e is Type) { ... } else { ... }`：

- 若 `e` 的类型为 `τ`，且 `τ` 与 `Type` 存在交集。
- 在真分支内，将 `e` 的类型更新为 `τ & Type`（若不相交则报错）。
- 在假分支内，将 `e` 的类型更新为 `τ - Type`。
- 对于 `if (e == null)` 等值测试，也可类似窄化。

对布尔运算符：

- `if (x is A || x is B)` 内部真分支处理较复杂，通常仅支持简单的模式。

#### 8.2 `match` 表达式与语句

`match e { case pattern => ... }`：

- 编译器分析 `e` 的类型，对每个 `pattern`，推导出该分支内变量的窄化类型。
- 对于 `unite` 类型，每个 case 对应一个具体子类，分支内 `e` 窄化为该子类。
- 对于 `union` 类型，穷举所有成员；若未穷举，则编译器要求 `else` 或报错。
- 模式内变量绑定：`case Some { value } =>` 会将 `value` 绑定到提取出的字段类型。

窄化是流敏感的，每个分支独立，分支结束后，类型恢复为合并（通常还原为原始类型或使用 union 构建）。

#### 8.3 `is` 作为条件时的其他形式

- `if let Some { value } = expr` 类似，将成功匹配的类型窄化到 `Some<T>`，并绑定 `value`。
- 类型检查器内部使用交差集统一处理所有模式窄化。

---

### 9. 泛型与约束检查

泛型函数 `micro f<T : C>(t: T) -> R / E { body }` 检查：

1. 在泛型环境中，`T` 被视为一个抽象类型，其方法行至少包含 `C` 定义的条目（若 `C` 为方法行约束），或其他约束。
2. 函数体内部，`t` 的类型为 `T`，调用 `t.m()` 时，类型检查器在 `C` 的行中查找 `m` 的签名，并用行变量处理其余部分。
3. 返回类型 `R` 与函数体的返回表达式类型兼容：`body_type <: R`。
4. 函数体累积的 effect 集必须 ⊆ `E`。
5. 当调用 `f(Point{})` 时，编译器推断 `T = Point`，并检查 `Point` 是否满足约束 `C`，即 `methods(Point)` 覆盖 `C` 中的方法且签名兼容。

泛型参数支持声明点方差，在实例化时子类型检查根据方差处理。

---

### 10. 类型兼容性判断（`IsAssignableFrom`）

赋值、传参等场合使用 `IsAssignableFrom(source, target)`：

- 检查 `source <: target` 是否成立。
- 若 `target` 是方法行约束 `{ m: ... }`，则检查 `methods(source)` 覆盖该行。
- 若 `target` 是 `any?`，永远成立。
- 若 `target` 是 `any`，要求 `source` 不能是 `null` 且 `null` 不是 `source` 的可能值（通过差集推导）。
- 若 `target` 是联合类型，拆解按规则判断。

---

### 11. Effect 检查与传播

1. 每个表达式计算时携带其 effect 集。
2. 序列表达式 `e1; e2` 的 effect 为 `ε₁ ∪ ε₂`。
3. 函数声明 `f() -> T / E` 时，函数体 effect `ε_body` 必须满足 `ε_body ⊆ E`。
4. 若调用一个带有 effect `ε_callee` 的函数，调用者的 effect 集将包含 `ε_callee`。
5. 类型检查器在函数边界检查 effect 一致性，不合规时报告 `VALK20xx` 错误。

### 12. 错误诊断代码

类型检查器在违规时产生诊断，代码范围 `VALK2001` ~ `VALK2029`（可扩展）：

- `VALK2001`：未定义符号
- `VALK2002`：类型不匹配
- `VALK2003`：方法未找到
- `VALK2004`：方法签名不兼容
- `VALK2005`：未穷举匹配
- `VALK2006`：Effect 未声明
- `VALK2007`：泛型约束不满足
- `VALK2008`：交集类型冲突
- `VALK2009`：差集窄化错误
- ……

具体诊断格式参见项目诊断文档。

### 13. 类型检查器内部架构

类型检查器由以下部分组成：

- `TypeChecker.cs`：主入口，遍历 AST 并驱动检查。
- `Scope.cs` / `Symbol.cs`：作用域与符号管理，支持窄化临时替换。
- `ValkyrieType.cs`：类型内部表示，包括方法行、类型种类、方差等。
- 约束求解器：处理行统一、子类型推导、交集/差集化简等。
- `MatchExhaustiveness.cs`：匹配穷尽性分析。
- `TypeNarrowing.cs`：实现窄化逻辑，基于交差集。

所有检查必须仅依赖公开方法行，不涉及对象内存布局或字段偏移。

---

### 14. 禁止事项与设计边界

- **禁止** 将字段存在性作为类型检查依据。
- **禁止** 在类型系统中直接操作对象布局或偏移。
- **禁止** 绕过 `TypeChecker` 在 `HIR/MIR` 中重复实现类型规则。
- **禁止** 将 `kont` 语义附加到字段上；只有方法执行流有续体效应。
- **禁止** 为单一后端（如 JVM/CLR/WASM）发明特殊的类型规则。
