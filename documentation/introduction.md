# Nyar 简介

## 问题：编译器构造的终极困境

所有编译器框架都面临同一个结构性问题：**如何同时容易地添加新语言构造和新分析/优化 Pass，且不修改已有代码？** 这就是 Expression Problem（EP）。

传统方案无法两全：

| 方案 | 添加新操作（分析/优化 Pass） | 添加新构造（语言特性） | 根本缺陷 |
|:---|:---|:---|:---|
| OOP 类层次 | ❌ 需侵入所有已有类 | ✅ 新增子类即可 | Visitor 缓解但不根治 |
| FP 模式匹配 | ✅ 新增函数即可 | ❌ 需修改所有已有函数 | 泛型/类型类缓解但不根治 |
| **OpCode 枚举 + Visitor** | ✅ 新增 Visitor | ❌ 修改枚举 + 所有 Visitor | 违反开闭原则，类型不安全 |

Nyar 旧架构采用第三种方案（OpCode 枚举 + Visitor），导致：
- `OpCode` 枚举随方言增长爆炸式膨胀
- 添加一个语言构造时，所有 Visitor 基类和实现必须同步更新
- 类型安全无法在编译期保证：`OpCode.Add` 的操作数可以是任意类型
- IDE、编译器、解释器需要各自维护一套代码路径

## 答案：对象代数

Nyar 新架构摒弃 OpCode 枚举，全面采用**对象代数**（Object Algebras）作为核心组织原则。

**核心理念**：将语言构造定义为**工厂接口的方法**，而非具体类或枚举值。程序本身成为一个多态函数，接受工厂实例，调用其方法来构造表示。

```csharp
// 方言 = 工厂接口（唯一定义）
public interface IArithAlg<E>
{
    E Lit(int value);
    E Add(E left, E right);
    E Mul(E left, E right);
}

// 程序 = 多态函数（不依赖具体表示）
static E Program<IArithAlg<E>>(IArithAlg<E> alg) =>
    alg.Mul(alg.Add(alg.Lit(1), alg.Lit(2)), alg.Lit(3));

// 同一程序，不同工厂 = 不同行为
var result = Program(new ArithEval());       // int: 9
var ast    = Program(new ArithAstBuilder()); // AstNode: Mul(Add(Lit(1), Lit(2)), Lit(3))
var egraph = Program(new ArithEgraph());     // EClassId: 送入优化器
```

详细机制请阅读 [对象代数](./core-systems/object-algebras.md)。

### 对象代数如何解决 EP

| 扩展维度 | 方式 | 是否需修改已有代码 |
|:---|:---|:---|
| 新增操作（新 Pass） | 实现新的工厂类 | ❌ 否：新工厂独立存在 |
| 新增语言构造（新方言） | 定义扩展接口 `INewAlg<E> : IOldAlg<E>` | ❌ 否：旧程序不受影响 |
| 新增后端 | 实现工厂接口，绑定 E 为目标表示 | ❌ 否：与已有后端无关 |

一句话：**两个维度都可以独立扩展，完全类型安全。**

## 四个应用，一套接口

对象代数使 Nyar 能够用同一套方言接口统一四大应用场景：

```
                      方言 OA 接口（唯一定义）
                      IDialectAlg<E>
                             │
        ┌──────────┬─────────┼─────────┬──────────┐
        ▼          ▼         ▼         ▼          ▼
    ┌───────┐ ┌───────┐ ┌───────┐ ┌───────┐ ┌───────┐
    │编译器  │ │ IDE   │ │解释器  │ │分析器  │ │扫描器  │
    │       │ │       │ │       │ │       │ │       │
    │EGraph │ │PSI    │ │NyarVM │ │类型   │ │模式   │
    │PE     │ │语法   │ │JVM    │ │效应   │ │等价   │
    │成本   │ │补全   │ │WASM   │ │引用   │ │搜索   │
    └───────┘ └───────┘ └───────┘ └───────┘ └───────┘
```

关键是：**方言 OA 接口是唯一的事实来源**。添加一个语言构造，IDE 自动获得补全、编译器自动获得优化能力、分析器自动获得检查逻辑——无需在多套代码路径中同步修改。

## 元编译器：OA 驱动的编译管线

Nyar 作为元编译器，接受任意语言的意图表示（OA 程序函数）、可扩展的重写规则和成本模型，自动生成针对该语言的专用编译器。

```
语言前端 (外部)         Nyar 元编译器核心 (OA 管线)          后端 (可选)
┌──────────┐    ┌────────────────────────────────────┐   ┌──────────┐
│ 源语言    │    │  程序函数 (OA)                       │   │ NyarVM   │
│ ↓        │    │  ↓                                  │   │ JVM      │
│ 意图构造  │───►│  EGraph 饱和 (OA 工厂: EClassId)       │──►│ WASM     │
│ (OA工厂)  │    │  ↓                                  │   │ Native   │
└──────────┘    │  部分求值 (OA 工厂: Static+Residual)    │   └──────────┘
                │  ↓                                  │
                │  成本模型选择 → 最优表示              │
                │  ↓                                  │
                │  代码生成 (OA 工厂: 目标数据结构)      │
                └────────────────────────────────────┘
```

## NyarVM 的定位

NyarVM 是 Nyar 的**一个运行时后端**，不是 Nyar 的全部。它提供了最完整的运行时支持（JIT、GC、代数效应、Witness Table），但 Nyar 的元优化能力（EGraph、PE、成本模型）适用于所有后端。

| Nyar 框架能力 | 适用后端 |
|:---|:---|
| EGraph 饱和优化 | 所有后端 |
| 部分求值 + Futamura 投影 | 所有后端 |
| 成本模型驱动的选择 | 所有后端 |
| 多目标代码生成 | 所有后端 |
| Witness Table 动态派发 | NyarVM 专属 |
| 代数效应统一控制流 | NyarVM 专属 |
| 精确非移动 GC | NyarVM 专属 |

## 与 Nova 论文的关系

Nyar 的 OA 架构直接借鉴了 Nova 元编译器论文的核心思想：**对象代数解决 Expression Problem，EGraph 提供穷尽优化，部分求值实现 Futamura 投影，PSI 连接 IDE 与编译管线**。Nyar 在此基础上进一步扩展了多后端运行时（NyarVM、JVM、WASM、Native）和多方言生态。

## 开发者角色的转变

| 传统模式 | Nyar OA 模式 |
|:---|:---|
| 编写 Visitor 处理每种 OpCode | 实现工厂接口的方法 |
| 修改 OpCode 枚举添加构造 | 扩展工厂接口 |
| 为每个目标手写代码生成器 | 声明降级目标，OA 自动适配 |
| IDE、编译器、分析器各自维护 | 方言 OA 一处定义，四处生效 |
| 调整 Pass 顺序 | 设计成本模型，EGraph 自动搜索 |

## 分层架构概览

Nyar 体系采用分层架构，从底层解析到顶层工具逐层构建：

```
┌──────────────────────────────────────────────┐
│     Nyar.Tooling (LSP, CLI, 测试工具)         │
└──────────────────────────────────────────────┘
                      │
┌──────────────────────────────────────────────┐
│     Nyar.Workspace (文件/项目/调度)           │
└──────────────────────────────────────────────┘
                      │
┌──────────────────────────────────────────────┐
│     Nyar.Semantic (符号/类型/索引/语义高亮)   │
└──────────────────────────────────────────────┘
                      │
┌──────────────────────────────────────────────┐
│     Nyar.Syntax (纯语法高亮、语法便利查询)    │
└──────────────────────────────────────────────┘
                      │
┌──────────────────────────────────────────────┐
│     Nyar.Intelligence (纯语法: 解析、AST、    │
│     Green/Red 树、增量重解析、语言注入)        │
│     原 Oak 2.0                               │
└──────────────────────────────────────────────┘
                      │
┌──────────────────────────────────────────────┐
│     Nyar.Binary (二进制编解码基础设施:        │
│     ByteBuffer、ICodec、IFrameProtocol、     │
│     BinarySerializable 源生成器)              │
│     原 Acorn                                 │
└──────────────────────────────────────────────┘
```

> **Nyar.Intelligence** 是整个体系的语法基石。它源自 Oak 2.0，提供不可变的 Green/Red 双树模型、CstBuilder 栈上构建器、ParseContext 解析上下文、增量重解析、语言注入、强类型 AST 手写基座等纯语法能力。详情参见 [解析基础设施文档](./core-systems/data-model.md)。
>
> **Nyar.Binary** 是整个体系的二进制基石。它源自 Acorn，提供零分配的 ByteBuffer/ByteBufferWriter、类型安全的 ICodec<T> 编解码器接口、泛型帧协议 IFrameProtocol、声明式 BinarySerializable 特性系统与源生成器。详情参见 [二进制框架概述](./binary/overview.md)。
