# Sonic / Hermes 使用者体验设计

## 概述

本文档定义 Hermes 与 Sonic 对**业务开发者（UX）**的最优 API 体验设计。
DX 指 Hermes/Sonic 的框架开发者，UX 指使用 Hermes/Sonic 编写业务代码的开发者。

### 核心约束

> **Hermes 完全独立，不知道 Sonic 的存在。抽象永不泄露。**

| 边界 | 规则 |
|------|------|
| **Hermes** | 编译器 + 生成器。产出 SchemaIR、纯数据记录（POCO）、DDL SQL、TS 客户端。无任何运行时依赖，不知 Sonic 为何物。 |
| **Sonic** | 运行时框架。消费同一个 SchemaIR，结合 `ISonic` 运行时能力生成 Repository、Cache Warper、Stream Warper 等运行时封装。 |

## 设计哲学

### 从"操作导向"到"实体导向"

用户的心智模型应当是"我定义了什么数据"，而非"数据该放哪个基础设施"。

```
操作导向（旧）                  实体导向（新）
─────────────────              ─────────────────
sonic.Save("user:1", u)        users.Save(u)
sonic.Load<User>("user:1")     users.GetById(1)
sonic.Put("user:1:cache", u)   users.Cache.Warm(u)
sonic.Emit("user.created", e)  users.Events.Created(e)
sonic.Query<User>().Filter()   users.FindByEmail("a@b.com")
```

### 零字符串地址

用户代码中不应出现任何地址格式（`"user:123"`）、键命名约定（`"user:cache:"`）、主题格式（`"user.created"`）。
这些全部由生成代码封装。

### 命名空间跟随业务

生成的代码的 namespace 跟随用户在 `.he` / `.hermes` 文件中声明的 `namespace`，绝不出现 `Sonic` 或 `Hermes` 字样。

```cpp
// schema/app.he
namespace Samsara;

model User { @@id: uuid, email: utf8, status: UserStatus }
```

生成产物：
- `namespace Samsara;` — User record（Hermes 产出）
- `namespace Samsara;` — IUserRepository（Sonic SourceGen 产出）
- `namespace Samsara;` — IUserCache（Sonic SourceGen 产出）

```

```

## API 设计

### 1. 纯数据模型（Hermes 产出，零运行时依赖）

```csharp
// generated/Hermes/Models/User.cs
// <auto-generated> 由 hermes 命令自动生成，修改无效

namespace Samsara;

public sealed record User
{
    public Guid Id { get; init; }
    public string Email { get; init; } = string.Empty;
    public UserStatus Status { get; init; }
}
```

特征：
- `sealed record` 或 `sealed class`，无任何基类、无任何接口
- 无 `System.Text.Json.Serialization` 之外的 Attribute（除非用户指定 target: json）
- 无构造函数注入、无 DI 依赖

### 2. Repository 接口（Sonic SourceGen 产出，消费 ISonic）

```csharp
// generated/Sonic/Repositories/IUserRepository.cs

namespace Samsara;

public interface IUserRepository
{
    Task<User?> GetById(Guid id);

    Task<User?> FindByEmail(string email);
    Task<List<User>> FindByStatus(UserStatus status);

    Task<User?> GetByEmail(string email);

    IUserQuery Query();

    Task Save(User user);
    Task Delete(Guid id);
}
```

查询方法推导规则：

| Schema 标注 | 生成方法 | 语义 |
|------------|---------|------|
| `[index(field)]` | `FindBy{Field}(value)` → `Task<List<T>>?` | 普通索引，可能多结果 |
| `[unique(field)]` | `GetBy{Field}(value)` → `Task<T?>` | 唯一索引，保证单结果 |
| `@@id`（主键） | `GetById(id)` | 主键查询 |

### 3. Repository 实现（Sonic SourceGen 产出）

```csharp
namespace Samsara;

internal sealed class UserRepository : IUserRepository
{
    private readonly ISonic _sonic;

    public UserRepository(ISonic sonic)
    {
        _sonic = sonic;
    }

    public Task<User?> GetById(Guid id)
    {
        return _sonic.Load<User>($"user:{id}");
    }

    public Task Save(User user)
    {
        return _sonic.Save($"user:{user.Id}", user);
    }

    // ... 其他方法
}
```

**关键**：字符串地址（`"user:{id}"`）仅存在于 Repository 实现内部，绝不出现在接口或业务代码中。

### 4. Cache Warper（Sonic SourceGen 产出）

```csharp
namespace Samsara;

public interface IUserCache
{
    Task<User?> Get(Guid id);
    Task Set(User user);
    Task Invalidate(Guid id);
}
```

内部委托 `ISonic.Get()` + `ISonic.Put()`，自动处理 Read-Through Cache。

### 5. Stream Warper（Sonic SourceGen 产出）

```csharp
namespace Samsara;

public interface IUserStream
{
    Task Emit(UserEvent payload);
    IAsyncEnumerable<UserEvent> Subscribe(CancellationToken ct = default);
}
```

事件类型（`UserEvent`）由 schema 中的 `stream` 定义自动生成。

### 6. 索引驱动查询

`.he` 中声明索引：

```cpp
[index(email), index(status), unique(email)]
model User {
    @@id: uuid,
    email: utf8,
    status: UserStatus,
}
```

IUserRepository 自动包含：

```csharp
// [unique(email)] → 单结果，返回 T?
Task<User?> GetByEmail(string email);

// [index(email)] → 普通索引，可能多结果（此处与 unique 冲突，实际以优先级高的为准）
// 如同时声明 [index(status)]
Task<List<User>> FindByStatus(UserStatus status);
```

### 7. 业务代码示例

```csharp
// src/Samsara/UserService.cs
namespace Samsara;

public class UserService
{
    private readonly IUserRepository _users;
    private readonly IOrderRepository _orders;

    public UserService(IUserRepository users, IOrderRepository orders)
    {
        _users = users;
        _orders = orders;
    }

    public async Task<User?> GetUser(Guid id)
    {
        return await _users.GetById(id);
    }

    public async Task<User?> GetByEmail(string email)
    {
        return await _users.GetByEmail(email);
    }

    public async Task<List<User>> GetActiveUsers()
    {
        return await _users.Query()
            .Filter(u => u.Status == UserStatus.Active)
            .Sort(u => u.Email)
            .ToListAsync();
    }

    public async Task<User> CreateUser(string email)
    {
        var user = new User
        {
            Id = Guid.NewGuid(),
            Email = email,
            Status = UserStatus.Inactive
        };

        await _users.Save(user);
        return user;
    }
}
```

用户代码特征：
- 只注入 `IXxxRepository`，不知道 `ISonic` 的存在（除非高级场景需要逐出缓存等）
- 所有方法签名类型安全，IDE 自动补全驱动
- 零字符串地址、零键格式约定

## 配置设计

### Hermes 配置（编译时，无 Sonic 依赖）

```json
// hermes.json 或 .csproj 属性
{
  "hermes": {
    "schema": "./schema/**/*.he",
    "output": "./generated/Hermes",
    "generators": ["csharp", "typescript", "sql-ddl"],
    "csharp": {
      "namespace": "Samsara",
      "target": "record"
    }
  }
}
```

### Sonic 配置（运行时）

Sonic 配置与 Hermes 完全分离，Hermes 不知道 Sonic 的存在。

方式一：Fluent API（推荐小项目 / 快速开始）

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddSonicData(options => options
    .UseDatabase(MySql.ConnectionFrom(builder.Configuration, "Sonic:Database"))
    .UseCache(Redis.Connection("localhost:6379").WithPrefix("app:"))
    .UseStorage(Local.Path("./uploads"))
    .UseStream(Kafka.FromEnvironment())
);
```

方式二：配置文件（推荐生产环境）

```json
// appsettings.json
{
  "Sonic": {
    "Database": {
      "Type": "mysql",
      "ConnectionString": "Server=localhost;Database=app;..."
    },
    "Cache": {
      "Type": "redis",
      "Endpoint": "localhost:6379",
      "KeyPrefix": "app:"
    },
    "Storage": {
      "Type": "local",
      "BasePath": "./uploads"
    },
    "Stream": {
      "Type": "memory"
    }
  }
}
```

```csharp
builder.Services.AddSonicData(builder.Configuration.GetSection("Sonic"));
```

方式三：环境变量

```
SONIC_DATABASE__TYPE=mysql
SONIC_DATABASE__CONNECTIONSTRING=Server=localhost;Database=app;...
SONIC_CACHE__TYPE=redis
SONIC_CACHE__ENDPOINT=localhost:6379
```

## API 分层

```
┌────────────────────────────────────────────────┐
│  Layer 3: Generated Repositories（业务层）       │
│  IUserRepository / IOrderRepository             │
│  用户 99% 的时间在这一层，完全类型安全              │
├────────────────────────────────────────────────┤
│  Layer 2: ISonic（统一入口层）                    │
│  Save / Load / Put / Get / Query / Delete /     │
│  Exists / Emit / On / Url                       │
│  用户需要动态地址 / 非典型场景时直接使用             │
├────────────────────────────────────────────────┤
│  Layer 1: Infrastructure（框架内部）              │
│  ISonicDatabase / ICacheService /               │
│  IStorageProvider / IStreamService              │
│  仅 Sonic Framework Builder 使用                 │
│  普通用户永远不会直接注入                            │
└────────────────────────────────────────────────┘
```

## 用户心智模型变化

| 概念 | 旧心智负担 | 新体验 |
|------|-----------|--------|
| "我的数据在哪" | 需要理解 DB / Cache / Storage / Stream 四层 | 只需知道 `IUserRepository`，缓存由框架透明处理 |
| "怎么存数据" | Save(user) — 但 key 是什么格式？ | `users.Save(user)` — 无歧义 |
| "怎么查数据" | `Query<User>().Filter(...)` — 每次写 lambda | `users.FindByEmail(email)` — IDE 补全 |
| "怎么配基础设施" | 理解 JSON 结构 + 四种 ServiceKind + 各后端参数 | Fluent API：`.UseCache(Redis.Connection("..."))` |
| "Schema 改了怎么办" | 改 .he → 跑命令 → 手动同步 Models → 改迁移 | 改 .he → 编译自动更新 → 改业务代码 |
| "新增一个 Model" | 改 .he → 跑命令 → 可能需要手动补充 C# 类 | 改 .he → IProductRepository 立即可用 |

## 独立 Hermes 用户 vs Sonic 用户

| | 纯 Hermes（无 Sonic） | Hermes + Sonic |
|---|---|---|
| **获取方式** | `Hermes.Compiler.Compile("app.he")` → SchemaIR | Sonic SourceGen 在编译时自动完成 |
| **消费方式** | 用户自己调用 `CSharpGenerator.Generate()` 获得 `string[]` | 编译时自动生成到 `generated/Sonic/` |
| **运行时能力** | 无。Models 只是纯 C# record | 有。`IUserRepository` 通过 DI 注入 |
| **配置** | 不需要运行时配置 | Fluent API / `appsettings.json` / ENV |

独立 Hermes 用户完全不存在"运行时基础设施"概念——他只关心代码生成。

## 实现优先级

| 阶段 | 优化项 | 所属项目 |
|------|--------|---------|
| **P0** | Hermes.Models 纯 POCO 全生成（CSharpGenerator，无运行时依赖） | Hermes |
| **P0** | Per-Model Repository 生成（IUserRepository 等，Sonic SourceGen 产出） | Sonic |
| **P0** | SonicModule 统一 DI 注册 | Sonic |
| **P1** | Index → Repository 查询方法推导（FindBy / GetBy） | Sonic SourceGen |
| **P1** | 配置体系统一（Fluent API + appsettings.json + ENV） | Sonic |
| **P2** | Cache / Stream 声明式生成（IUserCache / IUserStream） | Sonic SourceGen |
| **P2** | Service 定义 → Minimal API stub 生成 | Sonic SourceGen |
| **P3** | Source Generator 化（生成不入仓库，编译时自动同步） | Hermes + Sonic |
