# AI 与自我进化

## AI 注入点

Nyar 的架构为 AI 留出了三个清晰的注入点，分别对应规则发现、成本预测和策略选择。

### 注入点一：等价规则挖掘

**现状**：方言提供者需手动编写重写规则（如 a+b → b+a）

**AI 角色**：利用程序综合或强化学习自动发现领域内的等价变换

**具体机制**：

1. 输入：大量该领域的意图样本（例如，从开源代码库提取的 Tensor 计算图、SQL 查询日志、正则表达式库）
2. EGraph 枚举：在样本意图上运行 Nyar 的 EGraph（仅使用基础代数规则），生成每个样本的等价类空间
3. 候选提取：从等价类中提取成对的 (低成本表达式, 高成本表达式) 作为正样本
4. 规则归纳：使用反合一（Anti-Unification）在这些对中归纳出模式 (pattern -> replacement)，并附带适用条件
5. 输出：一组候选重写规则，经验证器（用随机测试或 SMT 求解器检查语义等价）过滤后，加入方言规则库

**Nyar 的优势**：

- EGraph 天然产生大量等价样本，无需额外插桩
- 成本模型提供自动标注（何者为优）
- 规则作用于 Nyar IR，跨前端语言通用

### 注入点二：机器学习成本模型

**现状**：成本模型多为基于静态计数的线性公式（如 cost = 10*loads + 2*adds）

**AI 角色**：训练神经网络预测实际执行成本（时间、内存、能耗）

**具体机制**：

1. 特征工程：将意图节点及其上下文编码为图神经网络（GNN）的输入
   - 节点特征：操作码、数据类型、张量形状（静态已知部分）
   - 边特征：数据依赖、控制依赖、内存顺序
2. 训练数据：Nyar 在真实硬件上运行大量意图变体，记录 Profiling 数据
3. 部署：训练好的模型作为可插拔成本模块，替代默认静态公式

**Nyar 的优势**：

- 持续学习：每次用户运行 Nyar 编译的程序，都可选择上报 Profiling 数据
- 跨硬件泛化：模型可接受硬件描述（如缓存大小、SIMD 宽度）作为额外输入

### 注入点三：搜索策略学习

**现状**：EGraph 提取最优解通常使用固定启发式（如自底向上动态规划）或束搜索

**AI 角色**：学习在何处应用规则、何时剪枝、如何分配搜索预算

**具体机制**：

1. 强化学习环境：状态 = 当前 EGraph 状态（嵌入表示），动作 = 选择一条重写规则并应用到某个 e-class
2. 奖励：最终提取出的程序的实测成本降低量
3. 训练：在小规模问题实例上训练策略网络，然后泛化到大规模意图

**Nyar 的优势**：

- EGraph 的饱和优化本质是搜索问题，正是 RL 擅长领域
- 学习到的策略可以固化为编译器的启发式，甚至生成专门的 pass 顺序

## 自举与固化

### 自举的阶梯

- **第 0 阶**：用现有语言（如 C# / Rust）实现 Nyar 核心（EGraph、VM、基础方言）
- **第 1 阶**：用 Nyar 前端方言（自己）编写 Nyar 的部分组件（如优化器、部分求值器），生成 .nyar 模块
- **第 2 阶**：Nyar 优化器优化自身的 .nyar 模块
  - 优化器内部的 Match 逻辑（模式匹配）被正则方言优化
  - 优化器使用的数据结构（如 HashMap）通过等价规则替换为针对当前负载特化的变体
  - 成本模型本身是一个意图，可被部分求值特化到特定硬件
- **第 N 阶**：优化后的优化器生成更优的代码，这些代码反过来再次优化优化器自身，形成正反馈循环

### 固化的机制

Nyar 的部分求值引擎是实现固化的关键。

**场景**：优化器在编译用户程序时，频繁计算某个复杂函数 `f(config, input)`。若 `config` 是编译时常量，PE 自动将 `f` 特化为 `f_config(input)`。

**固化**：若某个特化版本被反复使用，Nyar 可将其序列化为新的方言节点或重写规则，永久加入知识库。

**共享**：这些固化的规则/节点可通过包管理器分发，形成社区知识库。

## 与 LLVM/MLIR/Z3 的对比与超越路径

| 维度 | LLVM/MLIR/Z3 | Nyar 的进化路径 |
|------|--------------|-----------------|
| 优化知识来源 | 人类专家手工编码 Pass 和模式 | 人类提供基础规则 + AI 挖掘 + 自举固化 |
| 适应新硬件 | 需要人力编写新的调度模型和成本表 | 通过 Profiling 数据自动学习成本模型，自适配 |
| 跨领域协同 | 各领域优化器独立 | 统一意图空间，跨方言规则可自动发现 |
| 优化完备性 | 受限于专家编写的 Pass 顺序 | 饱和 EGraph 理论上可探索所有等价形式 |
| 起点 | 数十年积累，极其成熟 | 年轻，需要冷启动数据 |

### 超越路径

- **短期**：Nyar 在特定 DSL 领域（如张量计算、正则匹配）通过 AI 规则挖掘，达到甚至超越手写优化的性能
- **中期**：通过自举，Nyar 优化器自身的性能逼近手写 C++ 实现，并开始积累领域知识库
- **长期**：Nyar 成为一个优化知识的自动蒸馏器。任何程序员写的任何代码，只要在 Nyar 平台上运行，其 Profiling 数据和等价变换历史都成为进化养分

## 冷启动与验证

### 阶段一：作为现有工具的后端

Nyar 前端直接翻译现有 IR（如 ONNX、SQL AST、LLVM IR），仅使用手工规则进行优化。此时它不比 TVM 或 Calcite 差，但提供了一个统一的、可嵌入的优化库。

### 阶段二：引入 AI 辅助

在规则挖掘和成本模型上启用机器学习，开始在某些基准上超越手工调优。

### 阶段三：自举优化

Nyar 开始优化自身核心模块，降低运行时开销，吸引更多用户贡献 Profiling 数据。

### 阶段四：网络效应

Nyar 的规则和成本知识库通过社区共享，形成"优化维基百科"，任何新语言、新硬件都可快速获得高质量支持。

## 终极形态

Nyar 不再是一个静态的编译器，而是一个持续运行的、全球分布的优化生命体。它消化每一行代码的执行痕迹，分泌出新的等价规则和成本模型，反哺给每一个编译请求。人类专家从繁琐的 Pass 编写中解放，转向更高层的架构设计，而优化的细节则交由 Nyar 的自我进化完成。
