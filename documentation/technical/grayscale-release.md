# 灰度发布

> **归属：Layer 4 — 外围能力（运维）**
> **定位：** 灰度发布是部署策略，不影响 Persistent/Ephemeral 的语义

Sonic 的灰度发布通过 `sonic publish --canary` 实现，支持按流量比例逐步切换到新版本。

## 概述

灰度发布（Canary Release）是一种降低发布风险的策略：先将新版本部署到一小部分流量，验证无误后逐步扩大范围，最终全量发布。

## 使用方式

```bash
# 先发布到 10% 流量
sonic publish --canary 10

# 验证无误后扩大到 50%
sonic publish --canary 50

# 最终全量发布
sonic publish --canary 100
```

## 灰度维度

| 维度 | 说明 | 示例 |
|------|------|------|
| `traffic` | 按流量比例 | 10% 的请求到新版本 |
| `user_id` | 按用户标识 | 指定用户看到新版本 |
| `region` | 按地域 | 指定地区的用户看到新版本 |

## 灰度发布流程

```
sonic publish --canary 10
      │
      ▼
┌─────────────────────────────┐
│ 1. Schema Diff + 同步       │
│    与全量发布相同            │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│ 2. 构建前后端包              │
│    注入统一版本号            │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│ 3. 部署新版本到 Green 环境   │
│    流量仍指向 Blue (v1.0)    │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│ 4. 灰度切换 10% 流量        │
│    90% → Blue (v1.0)        │
│    10% → Green (v2.0)       │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│ 5. 监控与验证               │
│    错误率 / 延迟 / 业务指标  │
└──────────────┬──────────────┘
               │
         正常   │   异常
           │    │    │
           ▼    │    ▼
    扩大灰度    │   自动回滚
    --canary 50 │   切回 Blue
```

## 回滚

```bash
# 回滚到上一版本
sonic publish --rollback
```

回滚流程：
1. 负载均衡器将所有流量切回 Blue（旧版本）
2. Green 环境保留用于问题排查
3. 确认问题修复后，重新发布

## 与蓝绿部署的关系

灰度发布是蓝绿部署的渐进版本：

| 方式 | 流量切换 | 风险 | 适用场景 |
|------|---------|------|---------|
| 蓝绿部署 | 100% 一次性切换 | 中 | 小项目、低风险变更 |
| 灰度发布 | 逐步扩大 | 低 | 大项目、高风险变更 |

## 监控指标

灰度发布期间应关注：

| 指标 | 说明 | 阈值 |
|------|------|------|
| 错误率 | 新版本 API 错误率 | < 1% |
| 延迟 P99 | 新版本响应时间 | 不超过旧版本 20% |
| 业务指标 | 核心业务转化率 | 不低于旧版本 |
